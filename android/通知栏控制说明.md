# ZirconPods 0.4.0 通知栏控制

0.6.0 在原有四模式通知之外加入短时原生实时更新兼容测试，见 `ColorOS流体云说明.md`。四模式控制和蓝牙协议保持原有实现；最新主机检查共118项。

0.5.0 沿用本通知机制，并同步修正四模式图标与真无线耳机盒小图标。实验室切入极限降噪时，通知显示“当前：极限降噪”，四个基础模式均不错误高亮。最新验证为99项主机测试，详见README；下文保留0.4.0初版说明。

覆盖安装新版，打开应用并连接锆势。首次连接时允许通知权限；下拉通知栏即可直接切换“降噪、风噪、通透、普通”。四按钮顺序、圆形人像图标和蓝色选中样式沿用用户截图。折叠通知使用小图标适配系统高度，展开后显示大图标、当前模式、左右耳电量与“断开连接”。点击通知空白处可回到应用。

蓝色表示耳机已确认的模式。点击按钮后，展开通知会显示“正在切换…”，收到实际状态回包才改变选中态。五秒未确认时清除等待提示并保持已确认选中态，诊断日志保留提示。快速连续点击时，较早的回包可以更新实际模式，但不会冒充较新请求的完成回包。没有状态回包时不默认选中普通模式。

蓝牙控制器现在由 EarphoneService 持有。主界面只是绑定服务；返回桌面或关闭主界面不会主动断开正在连接/已连接的会话。通知不播放声音、不振动，不重复弹出。点击通知“断开连接”、耳机断开或连接失败后移除通知并结束前台运行。没有设备连接时不启动常驻通知。系统终止进程后不自动重连或重放模式命令，需用户重新连接。

通知权限拒绝不会阻止主界面控制。需要通知栏按钮时，进入右上角设置 → 通知栏控制设置，允许应用通知并开启“耳机模式控制”分类。应用仅首次连接主动请求通知权限。通知能否在锁屏显示、是否收起、卡片外框和通知清除行为由手机系统决定。

实现使用 Android 原生 RemoteViews 与 connectedDevice 前台服务，服务不导出，按钮使用显式、不可变 PendingIntent。四种模式仍使用既有锆势协议：09 01 降噪、09 04 风噪、09 03 通透、09 02 普通。没有加入联网权限、开机启动、定时轮询或后台自动扫描。

开发依据：[Android 自定义通知](https://developer.android.com/develop/ui/views/notifications/custom-notification)、[connectedDevice 前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device)、[通知运行时权限](https://developer.android.com/develop/ui/views/notifications/notification-permission)。

本机完成：79 项主机测试（59 项协议、20 项通知请求与回包状态测试）、Android 编译、DEX 打包、签名和对齐校验。主机测试覆盖未连接和非法模式拒绝、ACK/电量不改变模式、连续切换及延迟回包、请求超时、断开与重连清理。

当前没有连接的 Android 手机或可用模拟器。通知实际样式、按钮分发、退到后台后的控制和耳机固件行为尚未实机验证。实测时请依次确认：连接后通知出现 → 四模式可切换且选中态跟随耳机 → 返回桌面后仍可切换 → 通知断开按钮关闭控制会话 → 再次打开主界面能够重新连接。
