## Extreme noise cancellation — answered statically

ZirconDeviceConfig constructor at 0x6d26d0 creates DeviceLimitNoiseAncPanelItemWidgetModel at 0x6d2d50. This is an explicit model-specific UI configuration, stronger than a generic sender method existing somewhere in the app.

DeviceLimitNoiseAncPanelItem closure at 0xc38be4 reads the noise-mode state and compares against Smi 0x0a (integer 5) at 0xc38c60 to set the switch. It labels the feature `noise_anc_limit` at 0xc38c10. The enabling path displays RHints.showNoiseLimitModeBox, call at 0xc38dbc, before calling the intent.

DeviceDeepAncIntent.setDeepAnc (mixed-in method) at 0x78e89c:

- Enable: RCommander.setDeepAncOn at 0x78e978; call at 0x78e8d8.
- Disable: RCommander.setNoiseModeNormal; call at 0x78e930.

RsCommonV2Sender.get_setDeepAncOn at 0x7d5b8c writes Smi 18 and 12 at 0x7d5bb0..0x7d5bbc, giving raw payload `09 06`. Disable is raw payload `09 02`, ordinary mode. This is distinct from ordinary ANC `09 01`.

RsCommonV2Receiver.handleANCData at 0xf09aac builds a wire-to-UI map: `01 -> 3`, `02 -> 0`, `03 -> 1`, `04 -> 2`, `05 -> 4`, `06 -> 5`, `07 -> 6` (integer values after undoing Smi shift). Specifically `06` and Smi 10 are written at 0xf09b9c..0xf09ba8. RsCommonV2ReceiveHandler.ancDataReceived at 0xeec0c0 forwards that normalized state. A client retaining raw wire modes should treat `noise == 6` as extreme ANC selected, and other known modes as off. It should preserve unknown/unread state separately.

## Noise-cancelling touch cycle — answered statically

ZirconDeviceConfig creates DeviceAncLinePanelItemWidgetModel at 0x6d2db0 and assigns the constant allowed modes from PP+0x86f8 at 0x6d2dbc. Recovered constant array in array-recovered.json:

| UI identifier | Meaning |
| --- | --- |
| index:0 | Ordinary |
| index:1 | Transparency |
| index:2 | Wind |
| index:3 | ANC |

DeviceAncLinePanelItemWidgetModel.get_queryCommands at 0x7a3c30 returns PP+0x1df90. The independently recovered array contains RsCommonCommandEnum@2b4e7, name ANC_LIST, wire string `36`.

DeviceAncLineIntent.setAncLine (mixed-in method) at 0x79d6f8 passes booleans to RCommander.setAncLine at 0x79d948. Its state reconstruction establishes the register semantics: x3 maps to index:0 (ordinary), x5 to index:1 (transparency), x6 to index:2 (wind), x2 to index:3 (ANC).

RsCommonV2Sender.setAncLine at 0x7d0ff8 writes header Smi 108, raw 0x36, at 0x7d1038. It appends booleans in register order x2, x6, x3, x5. Therefore the exact raw payload is:

`36 <ANC> <WIND> <ORDINARY> <TRANSPARENCY>`

Each selected value is 01 and each deselected value is 00. Example ANC+transparency: `36 01 00 00 01`. All four: `36 01 01 01 01`. Do not serialize in the visual UI order without remapping.

Receiver dispatch compares string `36` (PP+0x12920, checked in array-recovered.json) at 0xefd294..0xefd2b0 and calls handleAncList at 0xf081d0. That method parses four hex-byte substrings in order and passes them as x2,x3,x5,x6. RsCommonV2ReceiveHandler.ancListDataReceived at 0xea41d0 adds index:3 for first byte ==1, index:2 for second ==1, index:0 for third ==1 and index:1 for fourth ==1, corroborating the same order.

The original UI permits deselecting an already-selected item only if the current count is greater than 2 (0xc3331c..0xc33354). This establishes the UI's minimum of two selected modes, not a proven firmware validation rule. A replacement should enforce 2–4 selections before writing. Incoming valid boolean state may be retained faithfully even if firmware replies with fewer choices; do not fabricate defaults as confirmed readings.

## Implementation and remaining limitations

- Both controls have model-specific static support in ZirconDeviceConfig. This does not prove all shipped Zircon firmware variants implement them identically.
- Sender payloads above must use the existing RFCOMM frame transformation; they are not complete framed bytes.
- Use acknowledged settings/data replies for UI selection. The original app also assigns optimistic local state; the replacement need not copy that behavior.
- A successful generic ACK is not a settings readback. Query ANC_LIST (`36`) via the established getInfo mechanism to synchronize the cycle after changing it; preserve separate unread state until the reply arrives.
- No physical earbud, HCI capture or running original application was available. No hardware execution or firmware acceptance was observed.
